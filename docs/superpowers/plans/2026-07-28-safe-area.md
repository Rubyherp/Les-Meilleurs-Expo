# Safe-Area Layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:subagent-driven-development` or `superpowers:executing-plans`.

**Goal:** Keep every route's content clear of device cutouts and home indicators without double-padding the tab navigator.

**Architecture:** Install one `SafeAreaProvider` at the Expo Router root. Add `SafeAreaView` at each route content boundary, using top-only edges for tab routes and top-plus-bottom edges for modal/full-screen routes. Preserve existing `ScrollView`, camera, and visual structure.

**Tech Stack:** Expo Router, React Native, `react-native-safe-area-context` (already present), TypeScript, NativeWind.

## Global Constraints

- Use `SafeAreaView` from `react-native-safe-area-context`, not the deprecated React Native implementation.
- Do not add dependencies or alter navigator presentation options.
- Do not add nested safe-area wrappers inside an already wrapped route.
- Preserve existing class-based padding and scroll behavior.
